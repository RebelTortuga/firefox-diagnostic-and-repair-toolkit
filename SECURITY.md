# Security Policy

## Reporting a vulnerability

Do not report exploitable vulnerabilities, credentials, or sensitive personal information in public issues or pull requests.

Use [GitHub private vulnerability reporting](https://github.com/RebelTortuga/firefox-diagnostic-and-repair-toolkit/security/advisories/new) when enabled (Security → Report a vulnerability). Include the affected release/commit, the impact, reproduction steps, and a minimal example without real credentials or private files.

If private reporting is unavailable, open a general issue requesting a private contact method. Do not include exploit details or sensitive attachments in that issue.

## Ordinary bugs and download warnings

Use Issues for non-sensitive bugs. For a download warning, include the file/version, official source URL, exact detection text, and security-product version; redact identifying paths. A detection should be investigated rather than presumed to be a false positive.

## Version information

Include the version or commit you tested. No fixed response-time, security-audit, or older-version support guarantee is made. Do not assume the newest release automatically resolves a reported vulnerability.
